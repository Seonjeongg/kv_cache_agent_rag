## 추가·보완 내용

1. State UUID와 LangSmith root run UUID를 연결하고 OpenAI 하위 호출을 기록한다.
2. 큰 분석 JSON의 뒷부분을 잘라내던 입력 절단을 제거했다. 부족한 보고서 절은 세 개씩 보완한다.
3. 잘못된 인용이 붙은 주장을 제거하고, 묶음 ID도 숫자로 변환한다. 저장 단계에서 내부 ID 잔존을 다시 검사한다.
4. MLA와 MoE를 구분하도록 검색 질의와 프롬프트를 보완했다. 짧아졌다는 이유로 교정 결과를 버리지 않는다.
5. 기존 조사 State로 보고서만 재생성하는 실행 모드를 추가했다. 새 조사 실행과 별도 trace로 구분한다.
6. README를 노션의 필수 절과 State 7항목, 실제 역할·기술 스택에 맞췄다.
7. 보고서 생성·절 보완에 문자열 전용 strict JSON Schema를 적용해 중첩 객체가 본문으로 노출되는 문제를 막았다. [OpenAI 공식 Structured Outputs 문서](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)를 확인했으며 모델은 기존 gpt-4o-mini를 유지했다.
8. 핵심 절은 실제 원문 발췌와 다시 대조하고, 본문과 근거 ID를 별도 필드로 받는다. 허용 ID만 선택할 수 있으며 출처 수를 채우기 위한 임의 인용은 넣지 않는다. 모델 버전 혼동과 수치 단위 오류를 줄이는 편집 규칙도 추가했다.

9. 원문 대조에서는 분석 요약을 다시 넣지 않아 오류의 반복을 줄이고, 기술 개요는 검색된 설명 문단을 사용한다. 목차는 근거에서 제외한다.

## 남아 있는 한계

- 형식적 Groundedness는 인용 ID의 존재·연결성 검사다. 각 문장이 원문에서 논리적으로 따라 나오는지 자동 입증하지 않는다.
- 출처 도메인 두 개는 독립 검증 두 개와 같지 않다. 독립 출처 allowlist가 비어 있으며 이 사실을 README에 표시했다.
- TRL은 공개 근거 기반 잠정 추정이다. MLA 구성요소와 DeepSeek-V2 모델 전체의 검증을 구분해야 한다.
- 시장성·관계자 요구는 실제 인터뷰나 채택 조사 결과와 분석자의 예상 요구를 구분해야 한다.
- 웹 검색 제한/실패 시 fallback을 사용한다. 추가 유료 계정을 만들거나 키를 바꾸지 않았다.
- 전체 실행은 Ollama·API 키·네트워크가 필요하다. 테스트 통과가 API 없이 전체 실행 가능하다는 뜻은 아니다.
