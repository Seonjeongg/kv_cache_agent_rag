# SUMMARY

본 보고서는 데이터센터에서 LLM 서빙 시 발생하는 KV cache 문제를 해결하기 위한 두 가지 기술, 즉 DeepSeek-V2와 ITME를 비교 분석합니다. DeepSeek-V2는 소프트웨어 계층에서 다중 헤드 잠재 주의 메커니즘을 활용하여 훈련 비용과 KV 캐시 사용량을 크게 줄이는 반면, ITME는 하드웨어 계층에서 CXL 하이브리드 메모리를 통해 메모리 효율성을 높입니다. 두 기술 모두 긴 컨텍스트 처리와 동시 사용자 수를 개선하는 데 중점을 두고 있지만, 각각의 접근 방식과 성능 특성에서 차이를 보입니다. DeepSeek-V2는 공개 배포된 모델로 TRL 8로 추정되며, ITME는 FPGA 프로토타입 기반으로 TRL 6으로 평가됩니다. 시장에서는 두 기술 모두 비용 효율성과 성능 최적화를 목표로 하고 있으며, 클라우드 사업자와 LLM 개발자 등 다양한 이해관계자들이 기대와 우려를 가지고 있습니다. 그러나 두 기술의 성능 비교는 실험 환경의 차이로 인해 직접적인 우열 판단이 어렵습니다. 향후 PoC 및 벤치마크를 통해 각 기술의 검증 질문을 우선적으로 다루어야 할 필요성이 있습니다.

# 1. 분석 배경

데이터센터에서 LLM 서빙 시 KV cache는 메모리 사용량과 긴 컨텍스트 처리, 동시 사용자 수와 밀접한 관계가 있습니다. KV cache는 모델의 성능과 자원 요구량에 영향을 줄 수 있으며, 메모리 압박이 심해질 경우 성능 저하가 발생할 수 있습니다. 이러한 문제는 데이터센터 운영에서 확인해야 할 요소지만, 실제 영향은 모델·하드웨어·동시성 조건에 따라 달라집니다. 본 보고서는 이러한 KV cache 문제를 해결하기 위해 소프트웨어와 하드웨어 계층에서 각각 접근하는 두 가지 기술을 비교합니다. 이 기술들은 서로 다른 계층에서 KV cache 병목을 다루므로, 경쟁 관계와 보완 가능성을 함께 평가할 수 있습니다. 공개 자료만으로 최적의 솔루션을 결정할 수는 없으므로, 적용 조건별 추가 검증 항목을 구분하는 데 목적을 둡니다.

# 2. 기술 선정

본 보고서에서는 소프트웨어 계층의 DeepSeek-V2와 하드웨어·메모리 계층의 ITME를 선택하였습니다. 두 기술은 동일한 KV cache 병목 문제를 해결하기 위한 접근 방식이 다르며, 각각의 기술적 특성과 성능을 비교할 수 있는 항목을 포함하고 있습니다. 그러나 두 기술의 성능 비교는 실험 환경의 차이로 인해 직접 비교가 어려운 항목도 존재합니다. 예를 들어, DeepSeek-V2는 소프트웨어 기반의 모델 최적화에 중점을 두고 있으며, ITME는 하드웨어 기반의 메모리 확장에 중점을 두고 있습니다. 이러한 차이는 각 기술의 적용 가능성과 성능을 평가하는 데 있어 중요한 요소로 작용합니다. 따라서, 각 기술의 성능을 비교하기 위해서는 동일한 조건에서의 실험이 필요하며, 이를 통해 보다 신뢰할 수 있는 결과를 도출할 수 있습니다.

# 3. 기술 개요

## 3.1 DeepSeek-V2 MLA

DeepSeek-V2는 다중 헤드 잠재 주의 메커니즘(MLA)을 활용하여 효율적인 모델 학습과 추론을 가능하게 하는 기술입니다. 이 기술은 다양한 자연어 처리 작업에서 성능을 발휘하며, 특히 대규모 언어 모델의 훈련 비용을 42.5% 절감하고 KV 캐시를 93.3% 줄일 수 있습니다. 또한, 최대 576%의 생성 처리량을 달성할 수 있는 성능을 보여줍니다. DeepSeek-V2는 긴 컨텍스트를 지원하며, 구현 및 서빙 요구사항이 기존 인프라에서 효율적으로 운영될 수 있도록 설계되었습니다. 그러나 이러한 성능 개선에도 불구하고, 구체적인 성능 수치가 제공되지 않아 비교 조건이 필요합니다. 이는 DeepSeek-V2의 성능을 평가하는 데 있어 한계로 작용할 수 있으며, 추가적인 검증이 필요합니다.

## 3.2 ITME

ITME는 CXL 하이브리드 메모리 구조를 통해 KV cache와 모델 데이터를 효율적으로 배치하거나 이동하는 기술입니다. 이 기술은 CPU 오프로드 및 프리패칭을 활용하여 메모리 압박을 완화하고, TTFT 속도를 개선하는 성능을 보여줍니다. ITME는 여러 동시 대화 처리에서의 효율성을 목표로 하며, 높은 대역폭과 낮은 지연 시간을 제공하는 인프라 요구사항을 갖추고 있습니다. 그러나 ITME의 성능은 특정 실험 환경에 의존하며, 다양한 환경에서의 일반화 가능성에 대한 추가 검증이 필요합니다. 이러한 한계는 ITME의 실제 적용 가능성을 평가하는 데 있어 중요한 요소로 작용할 수 있습니다.

# 4. 관점별 평가

## 4.1 기술 성숙도 및 TRL

DeepSeek-V2는 공개 배포된 모델과 관련 성능 근거가 확인되지만, 모델 전체의 배포 사실과 MLA 구성요소 자체의 실제 운영 근거는 구분할 필요가 있습니다. 따라서 본 보고서에서는 TRL 8을 공개 정보 기반의 잠정 추정으로 기록하며, 구성요소 수준의 운영 증거가 부족하다는 한계를 함께 둡니다. 이와 달리, ITME는 관련 환경에서 시스템 시연이 이루어졌으나 실제 운영 환경에서의 검증이 부족하여 TRL 6으로 잠정 추정합니다. 두 추정 모두 동일 조건의 현장 검증을 대신하지 않으며, 공개 정보의 범위에 따라 달라질 수 있습니다.

## 4.2 시장성

DeepSeek-V2는 효율적인 추론과 경제적인 훈련을 목표로 설계된 아키텍처이며, 원문에 보고된 실험 결과가 있습니다. 다만 공개 자료만으로 일반적인 상용 환경의 비용 우위나 도입 규모를 확정하기는 어렵습니다. ITME는 CXL 하이브리드 메모리를 활용하여 LLM 추론 메모리 용량을 확장하는 시스템 접근을 제시하며, 특정 실험 조건의 결과를 보고합니다. FPGA 프로토타입 및 관련 하드웨어 환경의 검증은 확인되지만, 일반적인 시장 채택이나 상용화 수준을 직접 확인하는 근거는 제한적입니다. 두 기술 모두 도입 장벽과 실제 구매·운영 비용에 대한 공개 정보가 부족하며, ITME의 소프트웨어 스택 의존성도 별도 PoC에서 확인해야 합니다. 따라서 이 절에서는 상용화 가능성을 단정하지 않고 추가 검증 질문을 남깁니다.

## 4.3 이해관계자

공개 자료에서 직접 확인된 이해관계자 발언과 도입 사례는 제한적이므로, 아래 내용은 기술 특성에서 도출한 검증 질문과 잠재적 기대·우려를 구분해 읽어야 합니다. 클라우드 사업자는 메모리·응답 시간 변화에 관심을 가질 수 있지만, 비용 감소를 확정할 직접 근거는 부족합니다. LLM 개발자는 MLA의 모델 구조와 서빙 구현 복잡성을 확인해야 하며, 서비스 개발자는 기존 스택과의 호환성·운영 부담을 검증해야 합니다. ITME의 경우 클라우드 사업자와 운영자는 메모리 확장 효과와 데이터 이동 지연을 함께 측정해야 하고, 하드웨어 공급자는 CXL 구성요소와 소프트웨어 스택의 통합 비용을 확인해야 합니다. 따라서 이 절의 기대·우려는 확정된 시장 반응이 아니라 공개 근거가 제한된 상태에서의 평가 항목으로 제시합니다.

## 4.4 데이터센터·클라우드 적용성

DeepSeek-V2는 원문 실험에서 KV cache 감소와 긴 컨텍스트 지원 근거를 제시하지만, 해당 수치를 다른 시스템 환경에 그대로 적용할 수는 없습니다. ITME는 GPU 메모리와 호스트 메모리를 함께 사용하는 긴 컨텍스트 KV cache 관리 방식을 제시하고 특정 동시 대화 실험을 보고하지만, 지연·대역폭·사용자 수 조건을 동일하게 맞춘 비교는 아닙니다. 따라서 두 기술의 도메인 적용성은 HBM 사용량, TTFT, 처리량, 정확도 영향, 데이터 이동 지연, 운영 비용을 동일 조건에서 추가 측정해야 합니다. 현재 공개 자료만으로 한 기술의 적용 우위를 확정하지 않고, 환경별 검증 항목으로 남깁니다.

# 5. 관점별 비교 및 상충 지점

DeepSeek-V2와 ITME는 KV cache 문제를 해결하기 위한 서로 다른 접근 방식을 가지고 있습니다. DeepSeek-V2는 소프트웨어 기반의 최적화에 중점을 두고 있으며, ITME는 하드웨어 기반의 메모리 확장에 중점을 두고 있습니다. 이러한 차이로 인해 두 기술의 성능 비교는 실험 환경의 차이로 인해 직접적인 우열 판단이 어렵습니다. 각 기술의 성능은 특정 조건에서 최적화되므로, 동일한 조건에서의 비교가 필요합니다. 이러한 비교의 한계는 각 기술의 실제 성능을 평가하는 데 있어 중요한 요소로 작용할 수 있습니다.

# 6. 시사점

기술 선택은 특정 서빙 조건에 따라 달라질 수 있으며, 각 기술의 검증 질문을 우선적으로 다루어야 합니다. MLA를 검토할 때는 모델 구조·지원 프레임워크·메모리 절감·정확도 영향을 확인하고, ITME를 검토할 때는 CXL 구성·데이터 이동 지연·운영 복잡도·비용을 확인해야 합니다. 어느 기술이 더 효과적이라고 결론내리기보다 동일한 입력 길이·동시성·하드웨어·측정 구간에서 PoC와 벤치마크를 수행해야 합니다. 현재 공개 자료만으로는 실제 운영 적용성을 확정하기 어렵습니다.

# 7. 분석의 한계

본 보고서는 논문 및 웹 자료를 기반으로 작성되었으며, 검색 품질과 실험 조건의 불일치로 인해 일부 정보가 부족할 수 있습니다. 또한, 공개되지 않은 비용, 운영 및 상용화 정보에 대한 한계가 있으며, LLM 생성 해석의 한계로 인해 기술의 실제 성능을 정확히 반영하지 못할 수 있습니다. 이러한 한계는 각 기술의 실제 적용 가능성을 평가하는 데 있어 중요한 고려사항이 될 수 있습니다.
